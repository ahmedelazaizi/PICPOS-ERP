# Patch: ربط اختصار «حسب المجموعة» بتقرير التصنيفات

`report-group-shortcut-wiring.diff` — **بينتقل بالحرف.** ملف واحد
(`lib/presentation/screens/reports_screen.dart`)، مفيش إشارة لـ `Brand`.

```bash
# من مجلد UralCash
git apply --3way /path/to/report-group-shortcut-wiring.diff
```

## الباج

في شاشة التقارير، شريحة «حسب المجموعة» تحت «تقارير المبيعات» بتفتح **تقرير
المبيعات العادي**، مش تقرير المبيعات حسب التصنيف. ونفس الحاجة تحت «تقارير
الأرباح».

النتيجة إن المستخدم يستنتج إن **التقرير مش موجود أصلاً** — وهو موجود
ومربوط فعلاً كإدخال رئيسي (`SalesByClassificationReport` تحت «التحليلات
والإحصائيات»). الشريحة هي اللي كانت كاذبة.

## السبب

`_ReportShortcut` مكانش فيها وجهة خاصة بيها — تلات حقول بس
(`id`, `title`, `parentReportId`). وكل مسارات الفتح كانت بتحل الأب وتنادي
`parent.action()` بلا أي وسيط تجميع:

```dart
final parent = cat.mainReports.firstWhere(
  (r) => r.id == s.parentReportId,
  orElse: () => cat.mainReports.first,
);
onTap: () { _registerOpen(s.id); parent.action(); }
```

يعني الـ ٣٧ اختصار كلهم مجرد أزرار بتفتح تقرير أبوهم. ده صح لاختصارات
زي «مبيعات اليوم» و«حسب الكاشير» (فلاتر جوه نفس التقرير)، لكن غلط
لـ «حسب المجموعة» و«حسب الصنف» اللي ليهم شاشات مستقلة.

## الإصلاح

`action` اختياري على `_ReportShortcut`، يُستخدم لو موجود:

```dart
(s.action ?? parent.action)();
```

والتوجيه:

| الاختصار | الوجهة |
|---|---|
| `s_group` «حسب المجموعة» | `SalesByClassificationReport` |
| `p_group` «حسب المجموعة» (أرباح) | `CategoryProfitReportScreen` |
| `s_product` «حسب الصنف» | `TopProductsReportScreen` |
| `p_product` «ربح كل صنف» | `TopProductsReportScreen` |

باقي الاختصارات بتفضل تسقط على تقريرها الأب بالسلوك القديم بالظبط —
`action` بتاعتهم `null`.

## ⚠️ اتظبط في مسارين مش واحد

الشاشة بتفتح الاختصارات من **مكانين**:

1. `_expandedShortcutChip` — الشريحة جوه كرت التصنيف
2. `_openFlatItem` — نتيجة البحث في مربع بحث التقارير

الاتنين اتظبطوا. لو ظبطت واحد بس، البحث عن «حسب المجموعة» هيوديك مكان
مختلف عن الضغط على نفس الشريحة — وده أسوأ من الباج الأصلي لأنه غير متسق.

## ملحوظة على `const`

قائمتا الاختصارات بتاعت `sales` و`profit` كانتا `const [...]`. الإدخالات
اللي ليها `action` مبقتش تقدر تبقى `const` (الـ closure بتقفل على `nav`)،
فالقائمة بقت عادية والإدخالات اللي لسه بلا وجهة فضلت `const` كل واحدة
لوحدها — مفيش خسارة في الأداء تُذكر، القائمة بتتبني مرة واحدة.

طبقة البيانات كانت جاهزة خلاص: `getSalesByCategory` و
`getCategoryProfitReport` في `sales_analytics_dao` — مفيش SQL جديد.
