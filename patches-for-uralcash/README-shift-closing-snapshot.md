## المشكلة

تقرير إغلاق الوردية كان بيتطبع **مرة واحدة** — على الورقة اللي خرجت من
الطابعة ساعة الإقفال. مفيش أي طريقة تشوفه أو تعيد طباعته بعد كده.

شاشة `shifts_report_screen` بتعرض صف الوردية الخام (متوقع/فعلي/فرق) بس، وزر
الطباعة فيها **stub** بيصدّر Excel:

```dart
// Use the same Excel export as a workaround for print — the user can open and print the file
await _exportToExcel();
```

## العائقان اللي منعوا حل بسيط

### ١. النافذة مالهاش نهاية

`getShiftClosingAggregates` نافذتها `[shiftStart, now]`. ده صح وإنت بتقفل
وردية شغّالة، لكن لو استخدمته لإعادة احتساب وردية **مقفولة** فالوردية اللي
اتقفلت الصبح هتبلع كل مبيعات اليوم اللي بعدها — والورقة المعاد طباعتها تطلع
بأرقام أكبر من الأصل.

**الحل:** بارامتر `shiftEnd` اختياري، افتراضيه `now`. **مسار الإغلاق الحيّ
ما بيتغيّرش خالص** (مبيبعتوش)، وبيتبعت بس عند إعادة احتساب وردية مقفولة.

### ٢. المبالغ الفعلية مش محفوظة

الفعلي اللي الكاشير عدّه وكتبه: `actual_cash` بس ليه عمود. الفعلي للبطاقة
وكليك كان مدفون جوه **نص** `notes`:

```dart
notes: 'إغلاق وردية POS - ${state.actualCardAmount > 0 ? 'بطاقة: ...' : ''}'
```

يعني إعادة حساب لوحدها **مستحيل** تطلع الورقة الأصلية. ده مش تفصيلة تجميلية:
ورقة إغلاق بأرقام مختلفة عن اللي الكاشير مضى عليها = مستند لا يصلح للمراجعة.

**الحل:** عمود `closing_snapshot TEXT NULL` على `shifts` (schema v151) بيتخزن
فيه JSON بكل أرقام التقرير لحظة الإقفال.

## اللقطة والطباعة من مصدر واحد

اللقطة بتتبني **قبل** `closeShiftWithAudit` وبتتخزن، والطباعة بتتم **منها**
عبر `printShiftClosingSnapshot`. الطباعة الأصلية وإعادة الطباعة بيعدّوا على
نفس الدالة — ده اللي بيضمن إن إعادة الطباعة هي نفس المستند مش شبيه متبني من
افتراضات تانية.

## الورديات القديمة

`closing_snapshot` بيفضل NULL للورديات المقفولة قبل الترقية — مفيش backfill
لأن مفيش حاجة تُسترجع. دي بيتعاد احتسابها بـ `shiftEnd` وبتتوسم صراحةً
**«معاد احتسابه — بدون لقطة أصلية»**، والفعلي للبطاقة/كليك بيتعرض «—» مش
`0.00` عشان الصفر يقرا كأنه عدّ فعلي بصفر.

وأرقام إعادة الاحتساب مطابقة حرفياً لتعريفات `PosClosingState`
(`invoiceCount = salesCount + returnsCount`، `cashIncome = salesCash` مش
`receiptCash`، إلخ) — أي انحراف هنا معناه ورقتين بنفس العنوان وأرقام مختلفة.

## المزامنة

- `api_handler` بيصدّر `closingSnapshot` مع باقي حقول الوردية
- `api_data_handler` بيستقبله في `/api/shifts/close` فوردية مقفولة من جهاز
  عميل يبقى لها لقطة على السيرفر كمان
- `shift_sync_strategy` بيطبّقه، وفي مسار التحديث بيستخدم **`Value.absent()`
  لو السيرفر ما بعتش المفتاح** بدل `Value(null)` — سيرفر قديم ميعرفش العمود
  كان هيمسح لقطة الجهاز المحلي

## الواجهة

الجزء ده PicPos-only ومش في الـ diff: تبويب «ورديات سابقة» في شاشة إغلاق
الوردية بيعرض نفس تقرير الأرصدة بتاع الإقفال (نقد/بطاقة/كليك: نظام · فعلي ·
فارق) مع زر إعادة طباعة، ووردية لسه مفتوحة بيعرض عليها تقفلها.

عندكم `shifts_report_screen` هي المكان الطبيعي لنفس الوظيفة.
