# Patch: «منع تراكم الأصناف» يخص أصناف الميزان وحدها

`prevent-stacking-weight-only.diff` — **بينتقل بالحرف.** مفيش إشارة لـ
`Brand`، وملفات PicPos متشالة من الـ diff. بيضيف كمان ملف اختبار جديد.

```bash
# من مجلد UralCash
git apply --3way /path/to/prevent-stacking-weight-only.diff
```

## الباج — الإعداد **مقلوب**، مش ناقص

ده مش «ميزة ناقصة». الإعداد `pos_prevent_item_stacking` كان بيعمل عكس
اللي اسمه بيقوله بالظبط.

### السلسلة

1. كل مسارات الإضافة (اللمس والباركود) بتمرّر قيمة الإعداد كما هي في
   `forceNewEntry` — **لكل الأصناف** بلا تفرقة.
2. وفي نفس الوقت `AddToCartUseCase` فيها الشرط ده:

   ```dart
   final shouldMerge = existingIndex >= 0 &&
       (!isSoldByWeight || mergeWeight) &&   // ← هنا
       !forceNewEntry && ...
   ```

   يعني صنف ميزان **ما بيندمجش أصلاً** إلا لو المستدعي بعت
   `mergeWeight: true`.
3. ومسار اللمس مكانش بيبعت `mergeWeight` خالص ⇒ بيفضل `false`.

### النتيجة

| | الإعداد مفعّل | الإعداد مغلق |
|---|---|---|
| **ميزان** | سطر جديد | سطر جديد ← **الإعداد مالوش أثر** |
| **عدد / حبة** | سطر جديد ← **الأثر كله وقع هنا** | يتراكم |

الإعداد اللي المفروض يخص الميزان مالوش أي أثر على الميزان، وكل أثره وقع
على أصناف العدد والحبة اللي المفروض تتراكم دايماً. كاشير بيدوس على نفس
زجاجة المية مرتين كان بيلاقي سطرين في السلة.

## الدلالة الصح

| نوع الصنف | الإعداد مفعّل | الإعداد مغلق |
|---|---|---|
| ميزان | سطر جديد كل وزنة | يتراكم في سطر واحد |
| عدد / حبة | **يتراكم دايماً** | يتراكم دايماً |

المنطق: الإعداد معناه «كل وزنة ميزان تبان لوحدها» — عشان الكاشير يشوف
0.750 + 0.400 كقراءتين من الميزان بدل 1.150 مبهمة. مكانش المقصود منه أبداً
إنه يمنع أصناف العدد من التراكم.

## الإصلاح

دالة واحدة جنب الـ use case اللي بيستهلك الأعلام:

```dart
({bool forceNewEntry, bool mergeWeight}) resolveStackingFlags({
  required bool isSoldByWeight,
  required bool preventStacking,
}) => (
  forceNewEntry: isSoldByWeight && preventStacking,
  mergeWeight:   isSoldByWeight && !preventStacking,
);
```

لاحظ إن `mergeWeight` **لازم** تبقى `true` للميزان لما الإعداد مغلق —
سيبها `false` معناها الشرط في الـ use case يفضل مانع الدمج، والإعداد يفضل
بلا أثر على الميزان زي ما كان.

وكل مسارات الإضافة بتعدّي عليها — مسار اللمس، ومسارات الباركود الستة في
`pos_search_controller` (ملصق الميزان، الاحتياطي، باركود الوحدة داخل فرع
الـ PLU، الباركود العادي بوحدة، الباركود العادي بلا وحدة، واحتياطي
السيرفر). **مفيش مكان تاني بيقرا الإعداد**، فمينفعش يتفرّعوا تاني.

### مسارات ملصق الميزان ما اتغيّرش سلوكها

كانت `mergeWeight: true` مع `forceNewEntry: forceNew`. الدالة بتطلّع نفس
النتيجة في الحالتين:

- الإعداد مفعّل: قديم `merge=true, force=true` ⇒ ما بيدمجش (لأن
  `!forceNewEntry` بتفشل). جديد `merge=false, force=true` ⇒ ما بيدمجش. نفس الشيء.
- الإعداد مغلق: قديم `merge=true, force=false` ⇒ بيدمج. جديد نفسه.

## عنوان الإعداد

بقى «منع تراكم أصناف الميزان (سطر لكل وزن)» مع tooltip يشرح إن أصناف
العدد بتتراكم دايماً. العنوان القديم «منع تراكم الأصناف (سطر جديد)» كان
بيوعد بحاجة تانية خالص — وده جزء من الباج مش تجميل.

## الاختبار

`test/unit/prevent_item_stacking_test.dart` (جوّه الـ diff) — ٨ اختبارات:
أربعة على مستوى الأعلام، وأربعة بتعدّي فعلاً على `AppToCartUseCase` وتتأكد
إن السلة بتطلع بالشكل الصح. الجزء التاني مهم عشان لو حد غيّر شرط الدمج جوه
الـ use case الاختبار يقع بدل ما الباج يرجع بهدوء.

المنطق pure — بلا UI ولا DB — فالاختبار بيجري في أجزاء من الثانية.
