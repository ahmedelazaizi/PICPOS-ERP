# خطة هجرة القوالب القائمة

الهدف: الانتقال إلى نموذج النطاقات (`EDITOR-ARCHITECTURE.md`) **بلا أن يستيقظ عميل واحد
على فاتورة مختلفة**. القاعدة الحاكمة: القالب الذي لم يمسّه المستخدم يجب أن يطبع بعد
الهجرة نفس البكسل الذي كان يطبعه قبلها.

---

## ١ · ما الذي يُهاجَر بالضبط

ثلاث مجموعات، ولكل منها خطر مختلف:

| المجموعة | العدد | الخطر | السبب |
|---------|------|-------|-------|
| قوالب مبذورة من `assets/invoice_templates/` | ٨ | منخفض | معروفة المحتوى ويمكن إعادة بذرها |
| قوالب هذا المجلد الجديدة | ١١ | معدوم | مكتوبة أصلاً بالبنية الصحيحة |
| قوالب أنشأها المستخدم في قاعدته | مجهول | **مرتفع** | لا نعرف محتواها ولا يمكن إعادة إنشائها |

المجموعة الثالثة هي التي تحكم الخطة كلها.

## ٢ · الاستدلال الأساسي — من التدفّق إلى النطاقات

القوالب الحالية تُرسم بالتدفّق (`sortOrder` + `flexWidth`) والإحداثيات مهملة. فالهجرة
**لا تقرأ `xPosition`/`yPosition` إطلاقاً** — لأنها لم تكن تؤثر على المطبوع، فاستعمالها
سيغيّر الشكل. تُشتقّ المواضع من التدفّق نفسه:

```
لكل قالب:
  ١ · وزّع العناصر على النطاقات بحقل `section` الموجود:
        header  → header
        body    → info ثم party  (الفصل بمفتاح العنصر: قائمة الطرف معروفة)
        details → details
        footer  → totals ثم footer (الفصل: مفاتيح المجاميع معروفة)

  ٢ · داخل كل نطاق، رتّب بـ sortOrder ثم امشِ صفاً صفاً:
        y الجاري = ٠
        لكل مجموعة عناصر متتالية flexWidth < 100 (صف واحد):
            العرض المتاح = عرض الورق − الهوامش
            نصيب العنصر = العرض المتاح × (flexWidth ÷ ١٠٠)
            x = تراكم أنصبة من سبقه في الصف (من اليمين)
            w = نصيبه
            h = ارتفاع سطر عند حجم خطه
        y الجاري += أعلى ارتفاع في الصف + ١مم

  ٣ · ارتفاع النطاق = y الجاري النهائي
  ٤ · details: يُعلَّم growsWithData = true دائماً
  ٥ · header و footer: repeatEachPage = true
```

هذا يعيد إنتاج التخطيط التدفّقي حرفياً بإحداثيات — فالمطبوع لا يتغيّر، والمستخدم يكتسب
القدرة على التحريك من اللحظة الأولى.

## ٣ · العناصر التي تحتاج معالجة خاصة

| الحالة | المعالجة |
|--------|----------|
| عنصر بلا `content` (القوالب المبذورة الثمانية) | يُستنتج المفتاح من `elementType`: `company_name` ⇒ `content = 'company_name'`. **هذا وحده يجعلها مرئية في المحرر لأول مرة** |
| `footer_text` محتواه المفتاح حرفياً | يُنقل النصّ إلى `labelAr` ويوضع محتوى افتراضي، أو يُحوَّل لـ`type: footer` |
| عنصر نصّ ثابت (`type: text`) | يبقى كما هو — `contentKey` فارغ و`labelAr` يحمل النصّ |
| `items_table` غائب من القالب | الراسم يُقحمه استدلالاً اليوم (`layoutSequenceForPrint` تُرجع `null`). الهجرة **تُثبّته** كعنصر صريح في نطاق details |
| عناوين أعمدة | تُملأ من الحرفيات الحالية (`الإجمالي` · `الضريبة` · `الخصم` · `السعر` · `العدد` · `الكود` · `الصنف` · `م`) ويُترك `labelEn` فارغاً ليملأه المستخدم |
| `headerBgColor` غير الافتراضي | يُنقل، لكن يُعرض تحذير في المحرر: «هذا اللون لا يصل الطابعة الحرارية» |

## ٤ · الترتيب — مع إمكانية التراجع في كل خطوة

**خطوة ٠ · نسخة احتياطية.** قبل أي هجرة، تُصدَّر كل قوالب المستخدم إلى JSON بالصيغة
الحالية وتُخزَّن في `backups/templates-{date}.json`. هذه شبكة الأمان الوحيدة للمجموعة
الثالثة.

**خطوة ١ · الكتابة على التوازي لا الاستبدال.** تُضاف أعمدة النطاقات الجديدة بجانب
القديمة ولا يُحذف شيء:

```dart
// migration v{N}
ALTER TABLE invoice_template_elements ADD COLUMN band_id TEXT;
ALTER TABLE invoice_template_elements ADD COLUMN x_mm REAL;
ALTER TABLE invoice_template_elements ADD COLUMN y_mm REAL;
ALTER TABLE invoice_template_elements ADD COLUMN w_mm REAL;
ALTER TABLE invoice_template_elements ADD COLUMN h_mm REAL;
ALTER TABLE invoice_template_elements ADD COLUMN condition TEXT;
ALTER TABLE invoice_templates ADD COLUMN layout_version INTEGER DEFAULT 1;
```

`layout_version = 1` تعني تدفّق، و`2` تعني نطاقات. الراسم يقرأ العمود ويسلك المسار
المناسب. **فالقوالب غير المهاجَرة تعمل كما هي بلا أي تغيير.**

**خطوة ٢ · هجرة القوالب المبذورة الثمانية.** معروفة المحتوى، ونتيجتها قابلة للمقارنة
بالعين. تُهاجَر وتُرسم قبل وبعد ويُقارن الناتجان.

**خطوة ٣ · هجرة قوالب المستخدم — كسولة لا دفعة واحدة.** القالب يُهاجَر **عند أول فتح
في المحرر** لا عند الترقية:

```
فتح قالب في المحرر
  └→ layout_version == 1 ؟
       └→ اشتقّ النطاقات (§٢) · احفظ بـ layout_version = 2 · اعرض شريطاً:
          «حُدِّث هذا القالب لنموذج النطاقات — راجع الشكل قبل الحفظ»
          [تراجع] يعيد layout_version = 1
```

سببها: الترقية الجماعية تلمس قوالب قد لا يفتحها المستخدم أبداً، وأي خطأ فيها يظهر على
ورق عميل لا على شاشة. الهجرة الكسولة تجعل كل تحويل مصحوباً بعين بشرية.

**خطوة ٤ · حذف الأعمدة القديمة.** بعد إصدارين على الأقل، وبعد أن يصير
`SELECT COUNT(*) WHERE layout_version = 1` صفراً عند غالبية القواعد.

## ٥ · فحص المطابقة — لا هجرة بلا قياس

قبل اعتماد أي قالب مهاجَر:

```dart
test('migration preserves output', () async {
  for (final t in seedTemplates) {
    final before = await renderLegacy(t);   // المسار التدفّقي
    final after  = await renderBanded(migrate(t));
    expect(pageCount(after), pageCount(before));
    expect(textRuns(after),  textRuns(before));       // نفس النصوص بنفس الترتيب
    expect(maxDrift(after, before), lessThan(1.0));   // انزياح أقل من ١مم
  }
});
```

`maxDrift` أهمّها: انزياح تحت المليمتر لا تراه العين، وفوقه يعني أن الاشتقاق أخطأ.

## ٦ · الرابطات — تُشتقّ من `isDefault` القائم

جدول `TemplateBindings` الجديد يُملأ آلياً من العَلَم الحالي:

```
لكل قالب isDefault = true:
    documentType = خريطة الفئة → نوع المستند
        receipt  ⇒ sales_receipt
        invoice  ⇒ sales_invoice
        purchase ⇒ purchase_invoice
        kitchen  ⇒ kitchen_order
        quotation⇒ quotation
    branchId = null · printerId = null · locale = null   ← يطابق الكل
    priority = 0
```

فينتج سلوك مطابق لليوم بالضبط، ويكتسب المستخدم القدرة على إضافة رابطات أخصّ فوقه.

**المرتجعات:** لا رابطة تُشتقّ لها لأنها لا تملك فئة. تُنشأ رابطة صريحة تشير لنفس قالب
الفاتورة، فيبقى السلوك كما هو، ويظهر المسار في شاشة الحسم موسوماً «تصادم فئة» حتى ينشئ
المستخدم قالباً خاصاً.

## ٧ · ما يراه المستخدم

| المرحلة | ما يراه |
|--------|---------|
| بعد الترقية مباشرة | لا شيء. كل شيء يطبع كما كان |
| أول فتح لقالب قديم | شريط: «حُدِّث لنموذج النطاقات — راجع قبل الحفظ» مع زر تراجع |
| بعد الحفظ | النطاقات ظاهرة في المحرر، والسحب يعمل، والمطبوع كما كان |
| القوالب الجديدة | تُنشأ بنموذج النطاقات مباشرةً |

## ٨ · معايير التراجع

يُوقَف الطرح ويُعاد `layout_version` إلى ١ لو ظهر أيٌّ من:

- بلاغ واحد بمطبوع مختلف عن السابق لقالب لم يُعدَّل
- `maxDrift` فوق ١مم في أي قالب مبذور
- قالب يفتح في المحرر بعناصر مفقودة
- زمن الرسم زاد أكثر من الضعف

النسخة الاحتياطية من خطوة ٠ تكفي لاستعادة أي قالب مستخدم يدوياً.
