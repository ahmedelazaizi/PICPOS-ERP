# تقرير الفواتير الملغاة بعد مرتجع

توفّر `AppDatabase.voidedAfterReturnReport()` كشفًا للقراءة فقط عن فواتير البيع التي حالتها `voided`، مع استبعاد مستندات المرتجع، والتي بقي لها دليل مرتجع حي. الدالة لا تغيّر أي صف أو رصيد.

يعتمد الكشف على شكلَي التخزين الموجودين في النظام:

- صف `sale_type='return'` غير محذوف، مربوط بالفاتورة في `notes` بالرقم أو بالمعرّف العالمي.
- حركات مخزون `sales_return` وحركات خزينة المرتجع المرتبطة بالفاتورة، مع استبعاد ما عُكس بحركة `return_cancel`.

يعيد كل صف رقم الفاتورة وتاريخها وإجماليها واسم الطرف (إن وجد)، وكمية المرتجع، وقيمة المرتجع المعروفة، ومؤشرات الانحراف الظاهرة. من أهم المؤشرات أن إلغاء الفاتورة أعاد كامل كمية البيع فوق كمية المرتجع السابقة؛ وهذا لا يعيد احتساب القيد ولا يقدّر تكلفة أو ذمم غير محفوظة.

حاليًا يُستعمل التقرير بواسطة مطوّر أو استعلام/أداة قراءة تستدعي الدالة، ولا توجد له واجهة مستخدم. على المحاسب مراجعة كل صف مع سجل المخزون والخزينة والأستاذ قبل إجراء قيد تصحيح معتمد.

## حدود الكشف

- لا يمكن إثبات مرتجع بلا صف ربط أو حركة تحمل المرجع المتوقع.
- القيمة تكون `null` إذا لم توجد قيمة موجبة معروفة في صف المرتجع أو حركة الخزينة.
- اختلاف صيغ قديمة أو مراجع غير صحيحة قد يمنع المطابقة.
- التقرير تشخيصي فقط: لا يصلح تلقائيًا المخزون أو الخزينة أو الذمم، ولا يستبدل المراجعة المحاسبية.
