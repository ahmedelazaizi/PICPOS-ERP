# اختبارات E2E لمنظومة PicPos

طبقة اختبارات طرف-لطرف تمرّ على **الطبقات الفعلية**: خادم السحابة الحقيقي (عملية `dart run` فرعية + PostgreSQL)،
عميل `picpos_api_client` الحقيقي، ومتحكمات/حالة كل تطبيق الحقيقية مع تخزين محلي في الذاكرة (لا جهاز ولا Keystore).
لا يوجد Mock للخادم في هذه المجموعات؛ الشبكة تُقطع فقط بغلاف يرمي استثناء الشبكة لمحاكاة «بلا إنترنت».

> سيناريوهات الأعمال على مستوى النظام (بيع/شراء/مخزون/خزينة/محاسبة/وردية/فترات مقفلة/صلاحيات/HTTP) بلا خادم ولا Postgres، وتعمل ضمن `flutter test` العادي: راجع [BUSINESS-SCENARIOS.md](BUSINESS-SCENARIOS.md) (`flutter test test/scenarios`).

## المتطلبات

- Flutter (القناة stable، 3.41) و`dart` في `PATH`.
- Docker مع حاوية PostgreSQL الاختبارية على المنفذ **55432** (`docker/docker-compose.yml`، خدمة `postgres`).
  المشغّل يفحص المنفذ ويشغّلها تلقائيًا بـ `docker compose up -d postgres` من مجلد `docker` إن لم تكن تعمل.
  متغيرات اختيارية: `TEST_DB_HOST` `TEST_DB_PORT` `TEST_DB_NAME` `TEST_DB_USER` `TEST_DB_PASSWORD`، و`E2E_DART` لتحديد ملف `dart`.
- كل نسخة خادم تفتح **schema معزولًا** (`e2e_<ts>_<rand>`) وتُسقطه عند الإغلاق؛ لا تلوّث بيانات أخرى.
- لا تُشغّل أمرَي `flutter` بالتوازي (قفل الإقلاع، وتعارض نسخ `sqlite3.dll` في `build/native_assets` للجذر).
  المشغّل تتابعي ويعيد المحاولة تلقائيًا (حتى 3) عند ظهور هذا التعارض.

## التشغيل

```powershell
# الكل بالترتيب مع جدول نهائي (رمز الخروج ≠ 0 عند أي فشل)
powershell -NoProfile -ExecutionPolicy Bypass -File tool/run_e2e.ps1      # أو: pwsh tool/run_e2e.ps1
# مجموعات محددة: server, packages, mobile, mobile_admin, mobile_pos, root, web
powershell -File tool/run_e2e.ps1 -Only server,mobile
powershell -File tool/run_e2e.ps1 -Skip root,web
# مزامنة نسخ المساعد المشترك بعد تعديل الأصل
powershell -File tool/run_e2e.ps1 -SyncHelpers
```

الترتيب: Postgres ← `server` ← `packages` ← `mobile` ← `mobile_admin` ← `mobile_pos` ← `root` ← `web`. سجلات كل مجموعة في `build/e2e_logs/<suite>.log`.

يدويًا (كل أمر من مجلده): `dart test -j 1 test/e2e` (server) · `dart test test/e2e` (packages/picpos_api_client) ·
`flutter test test/e2e` (mobile، mobile_admin، mobile_pos، والجذر) · `flutter test test/integration/web_client_e2e_test.dart` (الجذر، الويب).

## البنية المشتركة

| الملف | الدور |
|---|---|
| `server/test/e2e/support/e2e_server.dart` | يشغّل السحابة على منفذ حر: schema معزول + `seedDemo` + شركة ثانية فارغة (B)؛ يطبع `E2E_READY {json}`؛ يخرج ويُسقط الـ schema عند `stop`/إغلاق stdin. الخيار `--pair-limit=N` يرفع حدّ الاقتران (الإنتاجي 5/عنوان/10 د) لتعدد الاختبارات على خادم واحد؛ بدونه يُستعمل التوصيل الإنتاجي `CloudServices.create` كما هو. |
| `server/test/e2e/support/e2e_cloud.dart` | `E2eCloud`: يطلق الخادم كعملية فرعية، يتحدث HTTP بـ `dart:io` فقط، ويوفّر أدوار «المكتب» (`desktopLink`) والمندوب (`repPairingCode`). **الأصل**؛ منسوخ حرفيًا في `packages/picpos_api_client`، `mobile`، `mobile_admin`، الجذر (`-SyncHelpers`؛ المشغّل يحذّر إن اختلفت). |
| `packages/picpos_api_client/test/e2e/support/e2e_desktop.dart` (ونسخة في `mobile_admin`) | دور المكتب لتطبيق الإدارة: مفتاح Ed25519 حقيقي، دفع المستخدمين (PBKDF2) واللقطات الموقّعة، رموز الاقتران، إبطال الأجهزة. |

## ما تغطيه كل مجموعة

### `server` — `server/test/e2e/` (17 اختبارًا فعّالًا)
- `field_rep_journey_e2e_test.dart`: رحلة المندوب عبر HTTP: اقتران برمز+PIN (PIN خاطئ يُرفض) ← bootstrap (عملاء الخط فقط) ← مستندات «أوفلاين» (بيع آجل، سند قبض، سند صرف عهدة، زيارتان) تُدفع دفعة واحدة ← **replay**: كلها `duplicate` بلا خصم مخزون/رصيد مضاعف ← مستند مرفوض (عميل خارج الخط) ثم إصلاحه بنفس `globalId` فيُقبل ← تغذية المكتب (`ping`/`pending` بكل الأنواع) ← `ack` مختلط (ترحيل + فشل `period_closed`) ← **حل التعارض** بترحيل لاحق ← إبطال الجهاز من المكتب (كل النداءات 401 `device_revoked`) وإعادة اقتران جهاز جديد؛ وقواعد ترقيم المستندات (خارج النطاق/مستعمل).
- `admin_journey_e2e_test.dart`: رحلة تطبيق الإدارة: المكتب يدفع مفتاح التوقيع + مستخدمين + لقطات ← اقتران ودخول ← لقطات حسب الصلاحية (موافقات بلا `payroll`) ونطاق الفرع ← لقطة أحدث تفوز والأقدم تُتجاهل ← logout يُبقي الجهاز ← `unpair` (idempotent) يُبطل الجلسة والمكتب يرى `revoked` ← إبطال من المكتب ← تعطيل المستخدم يُبطل أجهزته.
- `security_cross_tenant_e2e_test.dart`: **عزل الشركات** (مكتب B لا يرى/يبطل أجهزة A، لا يصدر رمز اقتران لمندوب A، دفعة رئيسية من B بمعرّفات A لا تعدّل شيئًا، `ack` من B لا يرحّل مستند A، لقطات الإدارة لا تتسرّب بين الشركتين رغم تطابق `globalId` المستخدم)؛ **الرموز** (جلسة مزوّرة/مبدّلة/فارغة، رمز جهاز مع جهاز آخر، مفتاح إدارة/رابط مكتب خاطئ أو مخلوط، رمز اقتران وحيد الاستعمال، رابط مكتب مبطل، وتسجيل خروج يُبطل رمز الجلسة بحيث يُرفض طلب اللقطات اللاحق بـ401)؛ **replay** من جهازين ومن مندوب آخر؛ **القوة الغاشمة** (حدّ الاقتران 429 + `Retry-After`). كل مجموعة فرعية تشغّل خادمًا خاصًا بها لأن ميزانية الاقتران لكل نسخة خادم.

### `packages` — `packages/picpos_api_client/test/e2e/` (8)
`CloudManageClient` + `HttpApiTransport` الحقيقيان: اقتران ← دخول ← لقطات **تُتحقَّق بتوقيع Ed25519 حقيقي** بالمفتاح المثبّت؛ لقطة بمفتاح مزوّر ولقطة صحيحة التوقيع أُعيد تخزينها تحت نوع آخر (هجوم ريلاي) تُحتسب `rejected`؛ كلمة مرور خاطئة ثم قفل 5 فشل (`rateLimited` + `retryAfter`)؛ تطبيع الأرقام العربية-الهندية؛ إبطال من المكتب `deviceRevoked`؛ `unpair` من الجوال؛ نطاق الفرع؛ رمز اقتران مستعمل؛ عزل الشركتين.

### `mobile` (المندوب) — `mobile/test/e2e/van_rep_e2e_test.dart` (6)
`AppController` + `HttpCloudApi` الحقيقيان + `MemoryLocalStore`: اقتران برمز+PIN (رمز/PIN خاطئ) ← bootstrap ← **أوفلاين**: بيع آجل + سند قبض + سند صرف عهدة (مع العهدة المحلية) + زيارة ← المزامنة تفشل دون فقد شيء ← عودة الشبكة فتُقبل كلها مرة واحدة (المخزون/الرصيد صحيحان) ← مرتجع أوفلاين ثم مزامنة ← المكتب يرى كل المستندات ويرحّلها ← إبطال الجهاز من المكتب فيمسح التطبيق بياناته ويعود للاقتران. إضافةً: ضياع رد الدفع (يُقبل مرة واحدة)، رمز اقتران مستعمل، تدوير رمز الجهاز بعد 30 يومًا، جلسة مزوّرة ثم إعادة الدخول، الدخول بالـ PIN المحلي دون اتصال.

### `mobile_admin` — `mobile_admin/test/e2e/admin_app_e2e_test.dart` (8 + 1 مؤجَّل)
`AdminSession` الحقيقي (+ `PicPosAdminApp` فوق الخادم الحقيقي): اقتران بتثبيت مفتاح التوقيع ← دخول ← لوحة المؤشرات (`51.000`) وقائمة الموافقات ← تحديث من المكتب ← `restore()` بعد إعادة التشغيل؛ عدم تطابق مفتاح QR؛ لقطة مزوّرة لا تُعرض؛ قفل بعد 5 فشل؛ `unpairAndWipe` (الأسرار تُمسح والمكتب يرى revoked)؛ إبطال المكتب يمسح الأسرار عند أول `refresh`؛ تسجيل الخروج؛ ورحلة واجهة كاملة (نموذج الاقتران ← دخول ← لوحة ← موافقات ← إعدادات ← فك الربط).

### `mobile_pos` (الكاشير) — `mobile_pos/test/e2e/pos_app_e2e_test.dart` (2 + 6 مؤجَّلة)
المنفَّذ فعلًا في التطبيق هو هيكل M-0 (شاشة اقتران معطّلة + قشرة بلا شبكة)، فيُغطّى تدفق المستخدم الفعلي (اقتران معطّل ← معاينة ← بيع فارغ ← كل التبويبات ← الإعدادات ← العودة للاقتران). لا اختراع لسلوك غير موجود.

### `root` — `test/e2e/desktop_cloud_e2e_test.dart` (5)
خدمة المزامنة الحقيقية `CloudSyncService` + `CloudLinkApi` على قاعدة drift حقيقية في الذاكرة ↔ الخادم الحقيقي، مع جهاز مندوب عبر HTTP: ربط الشركة ودفع البيانات الرئيسية (الجوال يرى العميل/المنتجات/المخزون/الدفتر) ← مستندات الجوال تُسحب وتُرحَّل (فاتورة، قيود، مخزون، رصيد) ← الرصيد المخدوم لا يُحتسب مرتين ← إعادة التشغيل لا ترحّل مرتين؛ **تعارض حقيقي** (فاتورة بتاريخ بلا سنة مالية يرفضها المكتب بسببها فيصل السبب للسحابة) ثم **حله** بإنشاء السنة المالية وإعادة المحاولة؛ إبطال جهاز مندوب من المكتب؛ رابط مكتب مبطَل/سر خاطئ يعيد خطأ نظيفًا دون المساس بالبيانات المحلية. (الـ fixture منسوخ من `test/integration/cloud_sync_i3_test.dart` دون تعديله.)

### `web` — `test/integration/web_client_e2e_test.dart` (القائم، 2)
دخول حقيقي، قراءة عبر القناة، رفض كتابة/جدول غير مسموح. لا يُعدَّل؛ المشغّل يشغّله فقط.
